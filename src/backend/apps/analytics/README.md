# Django VoC 분석 대시보드

`/analytics/`는 기존 로그인 세션을 사용한다. 로그인 직원과 같은 회사 데이터에만 접근한다.
`analytics.read` 업무 권한이 부여된 직원이 조회할 수 있다. Task 9 스키마를 처음 적용하면 기존 관리자에게 이 권한을 부여한다. 적용 전에는 `staff_user.role = 'admin'`으로 검사한다.
관리자는 회사 전체와 회사 소속 팀을 조회할 수 있다. 팀 리더(`team_lead`)는 소속 팀의 실적을, 상담사는 소속 팀의 요약을 조회할 수 있다.
상담사 목록과 상세에서 관리자 계정을 제외한다.

- 기간은 한국시간 기준 최근 7일 또는 직전 7일이다. 팀과 기간을 바꾸면 즉시 조회한다.
- 회사·팀의 접수 통계는 티켓 목록과 같은 `visible_ticket`에서 집계한다.
- 감성 비율은 유효한 감성값을 가진 접수 건을 기준으로 계산한다. 카테고리 비율은 전체 접수 건을 기준으로 한다.
- 상담사 한 명의 상세에서 선택 기간과 직전 같은 길이 기간의 처리 완료 건수를 비교한다.
- 팀 범위는 회사·팀 통계에서 티켓의 현재 담당 팀을, 상담사 목록에서는 직원의 현재 소속 팀을 사용한다.

## 운영 데이터 연결

공용 스키마와 티켓 쓰기 기능은 별도 작업에서 연결한다. 다음 항목은 이력을 조회하는 계약이다.

| 지표 | 데이터 |
| --- | --- |
| 배정·이관·완료 | `ticket_event`와 `event_type`의 `assigned`, `transferred`, `answer_completed` 이벤트를 읽는다. 완료는 티켓별 첫 완료 이벤트를 실제 처리 상담사에게 집계한다. |
| 첫 응답 | 고객에게 발송한 직원 답변의 `ticket_message.sent_at`을 사용한다. 티켓별 첫 성공 발송을 집계한다. |
| 미회신 검토 | `collab_request`에서 `review` 유형의 `pending`과 `accepted`를 센다. |

연결할 이력의 저장 구조가 없다면 화면에 대시와 연결 대기 안내를 표시한다.
`VOC_ANALYTICS_TEST_DSN`을 격리된 PostgreSQL에 설정하고 `manage.py test apps.analytics`로 검증한다.
