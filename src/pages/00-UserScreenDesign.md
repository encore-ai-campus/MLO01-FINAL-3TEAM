# User Screen Design

- 임시 서비스명 : 섭명뭐(서비스명 뭐하지)
- 문서 버전 : 0.1v
- 갱신일자 : 2026-11-24

번호가 붙은 HTML 파일을 브라우저에서 바로 열 수 있다.


## 레이아웃 양식

- 업무 홈부터 공통 레이아웃을 사용한다. 화면은 상단 고정 바, 좌측 고정 패널, 본문으로 구성한다.
- 상단 고정 바에 로고·서비스명, 알림, 내 계정, 로그아웃 버튼을 표시한다. 오른쪽의 ‘로그아웃’을 누르면 **01-01 로그인**으로 돌아간다.
- 좌측 고정 패널은 업무 홈, 티켓 목록, 받은 요청, 팔로업 순으로 배치한다. 현재 화면에 해당하는 메뉴를 강조하고, 맨 아래에 ‘설정’을 둔다. ‘설정’의 상세 기능은 추후 정의한다.


## 01. 로그인

[로그인 시안 열기](./01-LoginPage/01-LoginPage.html)

### 01-01 로그인

- 사원은 회사 이메일과 비밀번호를 입력해 로그인한다.
- 회사 이메일 형식이 올바르지 않으면 이메일 입력란 아래에 안내한다.
- 회사 이메일을 비워 둔 채 로그인하면 이메일 입력란 아래에 ‘회사 이메일을 입력해 주세요.’를 표시한다.
- 회사 이메일 형식이 올바르고 비밀번호를 비워 둔 채 로그인하면 비밀번호 입력란 아래에 ‘비밀번호를 입력해 주세요.’를 표시한다.
- 비밀번호는 기본적으로 가린다. ‘표시’를 누르면 확인할 수 있고, ‘숨기기’를 누르면 다시 가린다.
- ‘비밀번호를 잊으셨나요?’를 누르면 **01-02 비밀번호 분실 안내**를 띄운다.
- 관리자가 비밀번호를 초기화한 사원은 전달받은 비밀번호로 로그인한다.
- 일반 로그인에 성공하면 **02-01 업무 홈**으로 이동한다.
- 시연 기간에는 로그인 화면 오른쪽 아래의 ‘업무 홈 시안 보기(임시)’로 02-01 업무 홈을 열 수 있다. 시연용 계정을 부여한 뒤 이 링크를 삭제한다.

### 01-02 비밀번호 분실 안내

- 로그인 화면에 어두운 배경을 덮고, 중앙에 ‘비밀번호 분실 안내’ 대화상자를 띄운다.
- 사원에게 회사 이메일과 함께 사내 관리자에게 비밀번호 초기화를 요청하도록 안내한다.
- 관리자가 초기화한 뒤 전달한 비밀번호로 로그인하도록 안내한다.
- ‘확인’을 누르면 안내창을 닫고 로그인 화면으로 돌아간다.

### 01-03 로그인 요청 중

- 로그인 요청을 처리하는 동안 버튼에 ‘로그인 중…’을 표시한다.
- 요청이 끝날 때까지 로그인 버튼을 비활성화해 중복 요청을 막는다.

### 01-04 로그인 실패

- 회사 이메일 또는 비밀번호가 올바르지 않으면 **두 입력란 모두**에 빨간 테두리를 표시한다.
- 입력란 근처에 ‘이메일 또는 비밀번호를 확인해 주세요.’를 표시한다.
- 사원은 입력값을 확인하거나 수정한 뒤 로그인 버튼으로 다시 시도할 수 있다.

#### 임시 규칙

- HTML 시안은 로그인 화면의 ‘업무 홈 시안 보기(임시)’로 열 수 있다. 카드 배치 저장은 같은 브라우저에서 확인할 수 있다.

## 02. 업무 홈

[업무 홈 열기](./02-WorkHomePage/02-WorkHomePage.html) · [화면 설정 열기](./02-WorkHomePage/02-WorkHomePage.html#02-02)

### 02-01 업무 홈

- 일반 로그인에 성공하면 개인 업무 홈으로 이동한다.
- 본문 카드의 기본 순서는 **내게 할당된 티켓 → 받은 요청 → 내 실적**이다.
- 오늘 배정된 티켓과 이전에 배정됐지만 처리가 남은 티켓을 표시한다. ‘전체 보기’를 누르면 **03-02 내게 할당된 티켓**으로 이동한다.
- 받은 요청에는 본인에게 들어온 검토 요청을 표시한다. 이관 요청의 표시 위치는 수락 절차를 확정한 후 정한다.
- 내 실적에는 오늘과 전날의 처리 건수를 표시한다. 처리 건수 집계 기준은 추후 확정한다.
- 본문 오른쪽 위의 ‘화면 설정’을 누르면 **02-02 화면 설정**으로 이동한다.
- 표시할 카드가 없으면 화면 설정에서 카드를 다시 표시할 수 있도록 안내한다.


### 02-02 화면 설정

- 업무 홈 본문의 카드별로 표시 여부를 켜거나 끌 수 있다.
- 카드를 드래그하거나 위·아래 이동 버튼을 눌러 카드 순서를 바꾼다.
- ‘기본 배치로 되돌리기’를 누르면 세 카드를 모두 표시하도록 설정하고 기본 순서로 복원한다.
- ‘저장’을 누르면 업무 홈으로 돌아가며 변경한 배치를 적용한다. 개인별로 설정을 저장해 다음 로그인 시 같은 배치를 표시한다.
- ‘취소’를 누르면 저장했던 배치로 업무 홈에 돌아간다.


## 03. 티켓 목록

[전체 티켓 열기](./03-TicketListPage/03-TicketListPage.html) · [내게 할당된 티켓 열기](./03-TicketListPage/03-TicketListPage.html#03-02)

### 03-01 티켓 목록

- 좌측 패널의 ‘티켓 목록’을 강조하고, 본문 상단에 ‘전체 티켓’과 ‘내게 할당된 티켓’ 탭을 표시한다. 전체 티켓 탭에는 열람 권한이 있는 티켓을 표시한다.
- 검색 대상은 제목, 고객 ID, 티켓 ID 중 하나를 선택한다. 검색어는 최대 50자까지 입력할 수 있다.
- 조회 결과 건수는 표 왼쪽 위에 표시한다. ‘페이지당 조회 건수’와 ‘필터 설정’은 표 오른쪽 위에 배치한다.
- 표에는 행 번호, 티켓번호, 제목, 카테고리, 담당자, 처리 상태, 감성, 최근 업데이트를 순서대로 표시한다. 행 번호는 현재 검색·필터 결과의 총건수부터 1씩 줄어든다. 페이지를 넘겨도 번호는 이어진다. 미할당 티켓의 담당자는 `-`로 표시한다.
- 표준화·저장이 완료된 티켓은 한 행씩 표시한다. 카테고리와 감성은 항목별로 ‘분석 중’ 또는 ‘분석 실패’를 표시한다. 감성 결과는 긍정·중립·부정·매우 부정을 색과 텍스트로 구분한다.
- 최근 업데이트에는 ‘1분 미만’, ‘5분 전’, ‘2일 전’처럼 경과 시간을 표시한다. 접수일자 오래된순 또는 최신순을 선택하면 그 아래에 접수 시각을 함께 표시한다. 접수 시각은 당일 `HH:mm`, 같은 해의 이전 날짜 `MM/DD`, 다른 해 `YYYY/MM/DD` 형식이다.
- ‘최근 업데이트’ 열 제목을 누를 때마다 기본 → 업데이트 최신순 → 업데이트 오래된순 → 접수일자 최신순 → 접수일자 오래된순 → 기본 순으로 전환한다. 기본은 접수일자 오래된순으로 정렬하고 업데이트 경과 시간만 표시한다.
- 페이지당 기본 조회 건수는 10건이다. 10·20·30·50건 중에서 선택할 수 있다. 전체 티켓 시안에는 예시 티켓 1,000건을 표시한다.
- 표 아래에 페이지 번호를 최대 10개씩 표시한다. 번호를 누르면 해당 페이지를 선택한다. `<`·`>`는 앞뒤 10개 묶음으로, `<<`·`>>`는 첫 페이지와 마지막 페이지로 이동한다. 첫 묶음에서는 왼쪽 화살표를, 마지막 묶음에서는 오른쪽 화살표를 숨긴다.

### 03-02 내게 할당된 티켓

- 로그인한 상담사에게 할당된 티켓을 표시한다.
- 전체 티켓과 같은 검색·필터·정렬 및 표 표시 규칙을 적용한다.

### 03-03 필터 적용

- ‘필터 설정’ 버튼을 누르면 처리 상태, 카테고리, 감성, 접수 기간을 한 창에서 설정한다.
- 처리 상태, 카테고리, 감성은 체크박스로 여러 항목을 선택할 수 있다.
- 접수 기간은 최근 1·3·7·30일 또는 ‘직접 지정’으로 선택한다.
- 필터가 적용되면 목록 위에 선택한 조건과 ‘초기화’를 표시한다.

### 03-04 검색 결과 없음

- 검색 또는 필터 조건에 맞는 티켓이 없으면 조회 결과를 0건으로 표시한다.
- 표 영역에 ‘검색 조건에 맞는 티켓이 없습니다.’와 ‘조건 초기화’ 버튼을 표시한다.

### 03-05 전체 카테고리 보기

- 필터 설정의 ‘전체 카테고리 보기’를 누르면 필터 창 오른쪽에 해당 고객사에 등록된 카테고리 목록을 표시한다.
- 카테고리는 체크박스로 여러 항목을 선택할 수 있다. ‘선택 완료’를 누르면 패널을 닫고 필터 설정으로 돌아간다.

### 03-06 접수 기간 직접 지정

- 접수 기간에서 ‘직접 지정’을 누르면 시작일과 종료일 달력을 나란히 표시한다.
- 두 날짜를 선택하고 ‘기간 적용’을 누르면 선택한 기간을 표시하고 필터 설정으로 돌아간다. 직접 지정 기간은 최대 365일이다.


## 후속_관리자 페이지 설계

- 관리자가 사원 계정을 발급하고, 계정을 조회하고 상태를 관리할 수 있어야 한다.
- 관리자가 사원의 비밀번호를 초기화할 수 있어야 한다. 사원은 초기화 후 전달받은 비밀번호로 로그인한다.
